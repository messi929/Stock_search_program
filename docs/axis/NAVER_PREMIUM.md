## 1. 스레드 마케팅 포인트 재점검

### 1-1. 현재 우리가 내걸고 있는 것

**프로필 bio** (실제 값):
```
새벽 미국장 정리부터 화제 종목까지, 매일.
강점만 보면 물리기 쉽죠. 약점도 같이.
🌙 시황 · 📈 종목분석
```

**공유 OG 카드 훅** (`web/app/stocks/[ticker]/opengraph-image.tsx:96`):
```
AI 4명이 리스크·성장·가치로 분석 — 추천은 안 합니다
```

### 1-2. 문제 세 가지

**① 1번 문장이 커머디티다.**
"새벽 미국장 정리, 매일"은 스레드 주식 계정 수백 개가 똑같이 내걸고 있다. 차별점이 아니라
**입장료**다. 그런데 우리는 이걸 첫 줄에 놓고, 진짜 차별점("약점도 같이")을 2번 줄에 묻었다.
방문자가 팔로우를 결정하는 데 쓰는 건 사실상 1번 줄이다.

**② 부정형 포지셔닝이 아직 살아 있다 — 세 번째 지적.**
`THREADS_FORMAT.md` §3에서 JEON이 두 번 지적했고(커밋 `becc450`, 문서 §3 카피 원칙),
생성 프롬프트에는 `guard_hedging`으로 막아뒀다. 그런데 **가드가 닿지 않는 두 곳에 그대로 남아 있다**:
- bio "강점만 보면 물리기 쉽죠" — 존댓말 + 부정형
- OG 카드 "**추천은 안 합니다**" — prod에서 모든 종목 링크 공유 시 노출

가드는 LLM 생성물에만 걸린다. **사람이 하드코딩한 카피는 가드 밖이다.**

**③ 톤이 갈라져 있다.**
본문은 전부 반말(§9에서 6개 생성기 전 타입 통일). bio는 존댓말. 프로필을 눌러본 사람이
보는 첫 문장과 글의 화자가 다른 사람이다.

### 1-3. 그런데 더 큰 문제

위 셋을 다 고쳐도 **조회 27은 안 움직인다.** 팔로워 24에서 브로드캐스트는 산술적으로 불가능하다.
카피 개선은 "프로필에 들어온 사람의 팔로우 전환율" 변수인데, **프로필에 들어오는 사람 자체가 없다.**

`THREADS_FORMAT.md`가 §2-5에서 이미 원인을 지목했다:
> 죽는 건 정보성이 아니라 **화자 없는 정보 + 답글 없는 브로드캐스트**

그리고 §6-④에서 "댓글이 제품이다"라고 결정했다. 그런데 실제로 구현된 건 §7 타래 인프라,
§8 루브릭 교체, §9 전 타입 최적화 — **전부 브로드캐스트 품질**이다. 유일한 도달 경로로
지목된 대화 루프는 "4단계"로 밀린 뒤 만들어지지 않았다.

**결론: 스레드에서 고칠 것은 글이 아니라 행동이다.** 발행량이 아니라 대화량이 24를 움직인다.
따라서 브로드캐스트 동결(2026-08-09 스케줄러 PAUSE)은 유지하고, 재개한다면 답글 중심으로.

## 2. 네이버 프리미엄콘텐츠 — 플랫폼 실체

| 항목 | 내용 |
|---|---|
| 성격 | 창작자 유료 구독 플랫폼 (2021-05 정식) |
| 구독료 | 월 2,900 ~ 19,900원 (창작자 설정) |
| 수수료 | **판매액의 10%** (네이버) |
| 상품 형태 | 구독형(월/연, 개인/그룹) + 단건 판매 |
| 페이월 | 본문 중 원하는 위치 지정 → 이하 유료 |
| 무료 발행 | 가능 (페이월 미설정) |
| 심사 | 영업일 **3~5일** |
| 개인 가입 | 가능. 단 전자상거래법상 **전화번호·사업장 주소 고시 의무** |
| 사업자 가입 | 사업자등록증(1년 이내)·통장사본·인감증명서(3개월 이내) |
| 발행 API | **없음** (스튜디오 웹 에디터 수동. 예약발행은 지원) |
| 검색 노출 | 네이버 검색 노출 설정 제공 |

### 2-1. 🚨 법적 게이트 — 유료화하면 유사투자자문업 신고 대상

금융위원회 법령해석(온라인 방송 사례)의 판단 기준:

> 신고 의무는 **"투자자로부터 금융투자상품의 투자조언과 관련해 직접적으로 대가를 수령하였는지 여부"**
> 를 기준으로 판단한다. 누구나 동일하게 무료로 받을 수 있는 조언은 직접적 대가가 없는 것으로 본다.
>
> - 광고수익만 발생 / 간헐적 자발적 후원 → **신고 불필요**
> - **유료회원제 운영(멤버십 등) 구독자로부터 직접적 대가 수령 → 신고 필요**
> - 유료회원과 1:1 상담 → 유사투자자문 아닌 **투자자문업 등록** 필요

프리미엄콘텐츠 유료 구독은 정확히 "구독자로부터 직접적 대가"다. 2024년 자본시장법 개정으로
유사투자자문업 규제·단속이 강화된 상태이기도 하다.

**그리고 이건 프리미엄콘텐츠만의 문제가 아니다.** Axis Pro(월 29,000원)는 2026-06-02부터
라이브다. 같은 법적 질문이 이미 본체에 걸려 있고, `project_ls_integration_remaining.md`의
"약관 변호사 검토"가 아직 미완이다. 프리미엄콘텐츠 유료화는 **이 미해결 리스크를
네이버라는 공개 플랫폼 위로 확대**하는 행위다.

- CLAUDE.md 하드룰: *"Axis는 투자자문업 면허가 없습니다"*
- `project_payment_decision.md`: 사업자등록 X

⚠️ **다만 "Axis는 추천을 안 하니까 투자조언이 아니다"는 스스로 판단할 문제가 아니다.**
"투자판단·가치에 관한 개별성 없는 조언"은 넓게 해석된다. 유료로 종목 수급·밸류 해석을 파는 것이
여기 걸리는지는 **변호사 확인 사항**이다.

### 2-2. 그래서 권장 = 무료 채널

페이월 없이 무료로만 발행하면 "직접적 대가" 요건이 성립하지 않는다 → 신고 의무 회피.
그러면서도 얻는 것:

- 네이버 검색 노출 (팔로워 0에서도 도달이 나는 유일한 경로)
- axislytics.com으로 보내는 깔때기
- 블로그 대비 **저품질(C-Rank) 리스크 구조가 다름** — 프리미엄콘텐츠는 심사를 통과한
  창작자 채널이라 신생 블로그의 누적 authority 문제를 우회한다

즉 **수익 채널이 아니라 유입 채널로만 쓴다.** 수익화는 Axis 구독으로 받고,
프리미엄콘텐츠 페이월은 변호사 검토 전까지 잠근다.

## 3. 시각자료 — 핵심

### 3-1. 에디터가 제공하는 블록 (전부)

사진 / 동영상 / 오디오 / 파일 / **종목** / **차트** / 페이월

**주의: 표(table)·인용·코드·구분선 블록은 문서에 없다.** 우리 콘텐츠는 수치 비교가 많아
표를 자주 쓰는데, **표를 못 쓴다면 그 자리는 전부 이미지로 대체해야 한다.**
→ 착수 전 스튜디오에서 실물 확인 필요 (문서 누락일 수도 있음).

### 3-2. 네이티브 증권 블록 두 개 — 성격이 정반대다

| 블록 | 범위 | 시점 | 제한 |
|---|---|---|---|
| **종목** | 국내만 | **독자가 조회하는 시점의 실시간 정보** | 콘텐츠당 최대 10개 |
| **차트** | 국내만 | **창작자가 작성한 시점** (정적, 자동 갱신 X) | — |

이 비대칭이 작성 전략을 거의 결정한다.

**종목 블록 = evergreen 안전.** 6개월 뒤에 읽어도 최신 수치가 뜬다. Axis의 하드룰
"실시간 검증 필수 / 데이터 신선도"를 **플랫폼이 대신 지켜준다.** 교육 콘텐츠처럼 오래 살아야 하는
글에 삽화로 넣기에 이상적이다.

**차트 블록 = 박제된다.** 작성 시점 차트가 그대로 굳는다. 검색 유입은 몇 달 뒤에 들어오는데
그때는 낡은 차트다. → **evergreen 글에는 차트 블록을 쓰면 안 된다.** 시황·브리핑처럼
"그날의 기록"인 글에만.

⚠️ 종목 블록 남용 주의: 한 글에 종목을 여러 개 박으면 시각적으로 종목 나열 글이 된다.
§1의 포지셔닝과도, 유사투자자문 색채 회피와도 어긋난다. **삽화로 1~2개.**

### 3-3. 우리가 직접 만들어야 하는 시각자료

네이티브 블록은 **가격 차트와 종목 시세**만 그린다. 그건 누구나 넣을 수 있는 것이고
차별점이 아니다. **Axis의 해자는 네이티브가 절대 못 그리는 그림에 있다:**

| 그림 | 왜 우리만 가능한가 | 데이터 출처 |
|---|---|---|
| **외국인 vs 기관 순매수 대비** | KRX 수급 5년 백필 보유 | `project_krx_login_blocker` 완료분 |
| **섹터 상대 위치** (내 종목 vs 업종) | 섹터 상대평가 스코어링 보유 | `screener/core/metrics.py` |
| **밸류 밴드** (PER/PBR 역사 분위) | fundamental band 잡 운영 중 | `jobs/backfill_fundamental_band.py` |
| **지표 분해** (같은 -6%의 세 갈래) | 교육 커리큘럼과 직결 | `agents/education.py` |
| **4사이클/국면 위치** | 매크로 정량 인프라 | `project_macro_infrastructure` |

`THREADS_FORMAT.md` §6이 말한 그대로다:
> 남들은 뉴스로 서사만 짜고 우리는 그 서사에 수급·섹터·밸류 **실측치**를 꽂는다.

스레드에서는 그 실측치가 **텍스트**였다. 프리미엄콘텐츠에서는 **그림**이 된다. 같은 무기인데
전달력이 다르다.

### 3-4. 생성 수단 — 이미 있다

**`next/og` (satori) 인프라가 prod에서 돌고 있다.**
- `web/app/stocks/[ticker]/opengraph-image.tsx` — 종목 카드 렌더링 실적
- `web/lib/og-font.ts` — 한글 글리프 서브셋 로더 (satori 기본 폰트에 한글 없음 문제 해결 완료)

업로드 규격도 여유롭다: **JPG/PNG/GIF, 파일당 최대 100MB, 첨부 총 20개.**
우리 카드는 수십 KB다. 개수·용량 어느 쪽도 제약이 아니다.

⚠️ **satori 함정 (이미 겪은 것 — `project_growth_tooling_and_prod_project`)**
- 한글 두부(□□□) → `loadKoreanFont()` 반드시 경유
- 자식 2개 이상이면 `display:flex` 명시 필수
- woff2 미지원 (ttf/otf/woff만), 번들 500KB 한도

**미보유**: 시계열 라인/캔들 렌더링. satori는 SVG 기반이라 선그래프는 path를 직접 계산해야 한다.
다만 위 표의 5종은 전부 **막대·점·밴드·위치 표시**라 satori로 충분하다. 캔들차트가 필요하면
그건 네이티브 차트 블록에 맡기면 된다. **역할 분담이 깔끔하게 갈린다.**

### 3-5. 시각자료 배치 원칙 (제안)

1. **첫 화면에 그림 1장** — 검색 유입은 제목 보고 들어와 3초 안에 이탈을 결정한다.
   그 1장은 "이 글에만 있는 그림"이어야 한다(= 우리 생성 카드, 네이티브 블록 아님).
2. **본문 중반 종목 블록 1~2개** — 삽화. evergreen 안전판.
3. **차트 블록은 시황 글에만.** evergreen 글에는 금지(§3-2).
4. **표가 필요한 자리는 전부 이미지로.** 에디터에 표 블록이 없을 가능성(§3-1).
5. **모든 수치 이미지에 기준일자 각인.** 그림은 캡처되어 돌아다니고, 우리 하드룰이 신선도다.

## 4. 콘텐츠 재고 — 이미 갖고 있다

교육 콘텐츠 33편이 Firestore에 있다. 스레드에서 평균 조회 16.7로 죽은 글들인데,
**훅을 보면 전부 네이버 검색어다**:

```
"PBR 0.8배면 싸다"는 말, 절반만 맞아
"골든크로스 떴다" — 그게 사라는 말인 줄 알았지?
매수가를 기준으로 "아직 덜 올랐어"라고 느낀 적 있어?   (앵커링)
"다들 산다는데 나만 놓치는 거 아냐?"                  (FOMO)
"여기서 팔면 손해 확정이잖아"                        (매몰비용)
```

콘텐츠가 나빴던 게 아니라 **채널이 안 맞았다.** 스레드는 검색이 없고 프리미엄콘텐츠는 검색이 전부다.

**단, 그대로 못 옮긴다:**

상위 계정의 반응 큰 글은 **전부 이미지가 붙어 있다.** `THREADS_FORMAT.md` §5-③은 이미지 첨부를
"공개 URL 호스팅이 필요하다"는 이유로 3단계로 미뤘고, 지금까지 우리 발행분은 **전부 텍스트 온리**다.
평균 조회 27의 원인 중 하나일 가능성이 높다.
→ §3-3의 시각자료 생성기는 프리미엄콘텐츠용이면서 **동시에 스레드용**이다. 하나 만들어 두 곳에 쓴다.
   호스팅은 이미 있다 — `next/og` 라우트가 공개 URL을 그대로 뱉는다.

**③ bio가 "무엇을 발행하는가"가 아니라 "왜 나를 믿는가"여야 한다.**
- 우리: `새벽 미국장 정리부터 화제 종목까지, 매일` → **발행물 목록**
- @_hee_r_chan: `월 수강생 100명 / 전문가 / 강남 자가 / 출간예정` → **자격 증명의 나열**
- @ho_ho_ju_ju: `매크로 · 섹터 · 리포트` → 영역 선언 + `호호주주 낙서장` → **사람 이름**

§1-2에서 지적한 커머디티 문제의 정확한 해법이 여기 있다. 그리고 §1의 "필명 애널리스트를 세워야
한다"는 결론과 같은 곳을 가리킨다.

**④ "분류표" 형태 — 서사도 종목분석도 아닌 제3의 포맷**
최고 반응(좋아요 3.7K, 공유 1.7K)은 `2026 미국주식 분류표`다. 서사(§8)도 아니고 종목글도 아니다.
**저장·공유되는 레퍼런스 자산**이다. 공유 1.7K는 좋아요가 아니라 "나중에 볼게"의 숫자다.

우리가 이걸 제일 잘 만들 수 있다 — 스크리너 카테고리, 섹터 분류, 밸류 밴드, 4,682 종목 DB가
전부 분류표 재료다. **§3-3 시각자료 목록에 "분류표"를 최상위로 추가해야 한다.**

### 7-5. ⚠️ 폐기한 검색 결과

조사 중 스레드 알고리즘 관련 검색이 SNS 툴 회사 블로그(snsboost / mirra / snsmeme)를 반환했고
"이미지 +60% 인게이지먼트" 같은 수치를 제시했다. `THREADS_FORMAT.md` §2-6이
**"다시 인용하지 말 것"** 으로 명시 폐기한 바로 그 장르라 채택하지 않았다.
§7-3의 이미지 결론은 그 수치가 아니라 **실제 계정 관측**에 근거한 것이다.

## 8. 구현 — ✅ prod 배포 완료 (2026-08-09)

두 트랙을 **완전히 분리해서** 세웠다(JEON 결정). 코드·타입·상수를 공유하지 않는다.

### 8-1. 프리미엄 트랙 (신규)

| 파일 | 역할 |
|---|---|
| `agents/premium_style.py` | 컬럼 문체·조립 단일 출처 |
| `agents/premium_weekly.py` | 주간 시그널 리포트 생성기 |
| `api/routes/premium.py` | 관리자 API `/api/admin/premium/*` |
| `web/lib/premium.ts` | API 클라이언트 |
| `web/app/(dashboard)/admin/premium/page.tsx` | 발행 워크스페이스 |

**"발행"의 의미가 스레드와 다르다.** 발행 API가 없으므로 `publish`는 발행 행위가 아니라
**발행 사실의 기록**이다. 화면 최상단에 고지 배너를 박아뒀다.

```
초안 생성 → 검수·수정 → [전문 복사] → 스튜디오 붙여넣기(사람) → URL 회수 → 발행 기록
```

URL을 요구하는 이유는 나중에 검색 유입을 계측하려면 실제 주소가 필요해서다.

**기호 위계는 코드가 붙인다**(`[  0 1  ]` `█` `▌` `───` `━━━` `██`). 두 이유:
① 복붙에서 서식은 깨져도 문자는 안 깨진다 — 발행 API 없는 환경의 실질적 해법
② 모델에 맡기면 매번 달라져 연재물 일관성이 무너진다

### 8-2. 🚨 데이터 소스 — Firestore `history`를 버렸다

### 8-3. LLM 산술은 못 믿는다 — 파생 계산을 코드로

모델이 거래대금 상위 8개 합산을 **54.01% 대신 58.01%** 로 썼다(가드가 잡음).
즉석 뺄셈에서도 174.01을 173.01로 틀렸다.

→ 누적 비중·상승 비율·규모 격차를 **코드가 계산해 facts에 넣고**, 프롬프트에서 직접
덧셈을 금지했다. 기호 위계를 코드가 그리는 것과 같은 원칙 — **결정론적인 건 결정론적으로.**

상승 비율 분모는 **보합 포함 전체**로 통일했다(빼면 82.6%가 87.4%로 부푼다).

### 8-4. 실측에서 잡은 그 외

- **'23개 업종' 환각** — facts에 업종 총 개수가 없으니 학습데이터 값을 가져왔다.
  `sector_count` 명시로 차단
- **"주가 5만원 넘으니 대형주일 것"** — 숫자는 맞는데 추론이 틀렸다. 수치 가드로는
  원리적으로 못 잡는 종류라 프롬프트에 금지 명시
- 업종 상/하위에 '제약'이 동시 등장하던 중복 제거
- '지수'라고 쓸 때 무엇의 지수인지 한정 요구
- 시스템 면책·미래 일정을 수치 대조에서 제외(`_factual_part`) — 안 그러면 **모든 초안에
  경고가 떠서 검수자가 경고를 무시하게 된다**
